## 2. B0：总览

### 0. 文档说明与项目总览

必须包含：

- 用途、读者、范围、项目性质和阶段；
- 作者职责与产品/算法/研发/业务/法务/安全/运营边界；
- 文档版本；
- 已确认事实、推断、假设、建议和待决策；
- 术语、对象 ID 和版本口径；
- 七问阅读法、本人手画提醒和原型缺口提醒。

**输出接口**：所有后续章节共享的事实边界和术语。

### 1. 一页纸项目摘要

必须在一页内回答：

- 为谁、在哪个场景、完成什么任务；
- 现状障碍和业务后果；
- 一期闭环和 AI 增量价值；
- 核心指标、红线、人工和上线前提；
- 当前最重要的 3—5 个决策。

摘要最后写证据状态，不要把后文的假设提前写成结论。

## 3. B1：业务与策略

### 2. 业务背景与问题定义

产物：

- As-Is 流程和角色；
- 痛点—根因—影响；
- 基线字段：量、时长、错误、成本、SLA；
- 不做成本；
- 北极星问题。

不要用宏观行业趋势替代本项目证据。

### 3. 用户研究与需求洞察

区分用户、受益者、买单者、审批者、规则 owner、安全 veto 和运营者。写研究方法、样本限制、关键任务、行为证据、现有替代和反例。

产物：

- 用户/角色/责任表；
- JTBD 或任务链；
- 需求证据卡；
- 需求—证据—优先级；
- 仍待验证的问题。

### 4. 产品策略与 AI 必要性

比较：

- 不做/延后；
- 优化 SOP/培训；
- 人工；
- 规则/搜索/SQL/RPA；
- 传统算法；
- RAG/LLM/Agent；
- 组合方案。

对每项说明能力边界、风险、成本、数据、运营负担和重评条件。明确一期非目标与不过度自动化原因。

### 5. 目标、指标与一期范围

将指标拆成：

- 业务结果；
- 用户任务；
- AI/规则质量；
- 安全红线；
- 稳定、时延、成本和人工容量。

每项写口径、来源、基线、目标状态、分层、频率、owner 和决策用途。目标没有实测时不能写成已达成。

MVP 表至少有：功能/场景、做或不做、理由、依赖、风险、验证。

**Gate A**：问题、AI 必要性、MVP、非目标和事实边界冻结后再进入详细方案。

## 4. B2：体验、功能和 AI 任务

### 6. 信息架构与整体体验

用图展示：

- 任务入口、对象、工作台、结果、人工和运营端；
- 正常、补件、降级、权限拒绝、无证据、处理中、失败和恢复；
- 业务对象与版本；
- 角色可见和可操作范围。

若无真实图片，明确原型缺口。企业落地原型需标注字段来源、状态、权限、危险动作、埋点和验收。

### 7. 核心功能 PRD

每个 P0 功能使用完整功能卡，不得只写功能一/二。至少覆盖：

1. 受理/输入；
2. 解析/结构化确认；
3. 核心 AI/规则任务；
4. 结果工作台与证据；
5. 人工确认/修改/例外；
6. 版本对比与重跑；
7. 外部写回/通知；
8. 运营/质量后台（若适用）。

每个功能至少提供正常、输入缺失、权限、并发/重复、依赖失败和恢复 Case。

### 8. AI 任务拆解与能力设计

先画全景图，再为每个任务写：

- 任务 ID、业务目标、输入、输出 Schema；
- Rule/RAG/LLM/Tool/Human 分工；
- 确定性业务不变量；
- 风险和禁止行为；
- 数据/Gold/指标；
- 降级、人工和版本。

必须解释规则审查做什么，并给业务 Case。不能只写“规则引擎先审查，RAG 再增强”。

**输出接口**：明确章节 9—12 要实现和评测的任务、对象、Schema 与责任。

## 5. B3：数据、模型、Prompt 与系统

### 9. 数据、知识库与 RAG

至少包含：

1. 数据地图与权威源；
2. 采集、授权、脱敏、质量、血缘、版本；
3. 清洗与结构化；
4. 冲突、过期、例外和发布治理；
5. 结构/语义/窗口/父子/表格等组合切片及 Why；
6. 上下文记忆与 Token 爆炸控制；
7. Embedding 候选、硬约束、业务评测和主备；
8. 向量库、索引、metadata、ACL、删除/对账；
9. Hybrid Retrieval、Query、过滤、Rerank、阈值；
10. Evidence Package、引用和无答案；
11. 离线/在线评测和异常降级；
12. 一个贯穿 Case 与消融。

### 10. 模型选型与方案决策

顺序：

`任务/风险 → 硬约束 → 候选池 → 初筛 → 业务评测集 → 质量/安全/时延/成本 → 主备/路由 → 灰度 → 重评`

硬约束可包括数据出域、部署、语言、上下文、结构化、工具、SLA、成本和供应链。不要先列模型名再找理由。

记录未胜出方案和 Why not。未知当前模型能力时，需查官方/一手资料或标待验证。

### 11. Prompt、Workflow 与 Agent

明确：

- Prompt 只负责什么、不负责什么；
- System/Task/Evidence/Output Contract；
- 证据 ID 白名单、引用和拒答；
- Schema 与业务不变量；
- Workflow 节点、路由、状态、超时、终止；
- 工具参数、权限、确认、幂等和返回；
- 多轮记忆来源、期限、压缩和删除；
- Agent 是否必要；若固定流程足够则不用 Agent。

### 12. 系统架构、接口与权限

图中展示：

- Client、Gateway、应用服务、解析、Rule、Retrieval、LLM、Validator、Workflow；
- Object Store、业务 DB、Rule Store、Knowledge Store、Vector Index、日志/Trace/Eval；
- 第三方系统和信任域；
- 在线请求、离线知识发布、人工和外部写回；
- 同步/异步、队列、缓存、幂等、对账和恢复。

接口契约写请求/响应、对象/版本、状态、错误、超时、重试、幂等、权限、日志和对账。

**Gate B**：功能、AI 边界、数据、模型、Prompt/Workflow、系统对象和人工责任能够贯通。

## 6. B4：异常、安全和评测

### 13. 正常、异常与边界

覆盖输入、模型、知识、工具、权限、状态、误用和 Corner Case。使用异常八格；给统一排查流程，强调找第一处错误而不是直接调 Prompt。

### 14. 降级、人工与恢复

解释 retry、degrade、handoff、reconciliation、circuit breaker、rate limit、kill switch、rollback。

人工六问：

1. 什么触发？
2. 谁接？
3. 接手包带什么？
4. 人具体做什么？
5. 结果如何回流？
6. 如何审计和恢复？

服务恢复必须判断任务是否仍需处理、对象是否仍是同一版本、人工/第三方是否已完成。

### 15. 安全、合规与责任

从保密、完整、授权、可追责出发。覆盖：

- 红线与风险分级；
- 隐私、敏感信息、出域和数据生命周期；
- Prompt Injection、知识投毒和供应链；
- 偏见和申诉；
- 高风险建议、决策和外部动作；
- 审计、责任和事件响应。

每条红线写攻击/失败输入、期望行为、检测证据和 Gate。

### 16. 评测、验收与发布 Gate

顺序：

`任务卡 → 风险 → 数据来源/分布 → Gold/仲裁 → 组件 → RAG/Agent/Tool → 端到端 → 红队/故障 → 成本容量 → Gate → 影子/灰度 → 在线复评`

必须写未通过动作。安全、高风险和权限不应用平均准确率抵消。

**输出接口**：上线所需的异常状态、人工容量、安全红线、评测集和 Go/No-Go 规则。

## 7. B5：归因、Bad Case 和运营

### 17. 数据分析与效果归因

埋点/Trace 必须关联用户、角色、对象/版本、场景、风险、每个组件版本、节点耗时/状态、人工动作和业务结果。

归因顺序：

`口径/流量 → 输入 → 解析 → 规则/知识/权限 → 检索 → Prompt/模型/校验 → Workflow/工具 → 交互/人工`

使用版本配对、消融、分层、原因码、故障注入和小流量实验，不把相关性写成因果。

### 18. Bad Case 闭环

区分反馈、Bad Case、事故和需求。流程：

`发现 → 记录 → 分级 → 止损 → 影响范围 → 根因 → 修复层 → 原/同类/反例/副作用回归 → 灰度 → 历史补处理 → 关闭`

代码合并不等于关闭。

### 19. 上线运营与持续迭代

所有改变线上行为的对象都要：

`owner + version + monitor + release Gate + rollback + recovery`

覆盖规则、模板、案例、政策、评测、模型、Prompt、索引、权限、Workflow、人工队列和成本。提供日/周/月/重大变更节奏及 Runbook。

**Gate C**：红线、评测、降级、补审、监控、回滚、对账和 owner 均可执行。

## 8. B6：交付、决策与答辩

### 20. 项目计划、资源、成本与风险

里程碑围绕消除不确定性：

`调研/基线 → 规则/数据准备 → PoC → 评测 → 影子 → 试点 → 运营`

每阶段写目标、交付物、进入/退出条件、角色、依赖、成本、风险和备选方案。计算全链路 TCO，包括专家、标注、人工兜底、事故和运营。

### 21. Decision Log

每个关键决策记录：

| 决策 | 目标/约束 | 证据 | 候选 | 选择 | Why not | 代价 | 风险 | 重评条件 | owner/date |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

至少覆盖：场景、AI 必要性、MVP、规则/AI 边界、RAG、模型、自动化/人工、指标/Gate 和发布范围。

### 22. 面试答辩材料

包括：

- 30 秒、3 分钟、10 分钟版本；
- 项目事实卡和个人职责；
- 业务/AI/数据/系统/评测/异常/安全/运营主问；
- 约束变化追问；
- 真实失败、冲突、反转判断；
- 可展示产物索引；
- 不知道或无真实数据时的诚实回答。

答题结构优先：

`场景/目标 → 约束 → 候选 → 决策和 Why not → 个人动作/协作 → 证据 → 结果或待验证 → 反思/重评`
