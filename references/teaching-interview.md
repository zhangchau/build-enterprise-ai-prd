## 1. 教学目标

读者看完后应能：

1. 复述本项目从业务输入到上线运营的完整链路；
2. 解释每个关键决策的 Why、Why not 和代价；
3. 替换行业变量后重新推导，而不是复制合同审查答案；
4. 手画流程、架构、状态和恢复；
5. 面对预算、数据、安全、规模或故障约束变化，指出哪些决策失效；
6. 诚实区分真实经历、课程设计、假设和建议。

只会背章节结论，不算掌握。

## 2. 每章阅读卡

每个一级章节开头增加简短 callout：

> [!tip] 本章怎么读、怎么迁移
> **最该注意**：……
> **阅读顺序**：先……再……
> **迁移到你的项目**：替换……，重新验证……
> **面试常问**：……

内容要求：

| 字段 | 写法 |
| --- | --- |
| 最该注意 | 一个核心决策，不是章节摘要 |
| 阅读顺序 | 告诉零基础读者先看对象/流程/指标中的哪一个 |
| 迁移 | 指出可复制的方法和不可复制的业务变量 |
| 面试 | 直接连接项目中的具体取舍 |

不要每章重复“关注业务价值和用户体验”。

### 四遍阅读法

| 遍次 | 问题 | 章节 | 学员产物 |
| --- | --- | --- | --- |
| 业务 | 谁完成什么高成本任务？ | 1—5 | As-Is、证据卡、北极星问题 |
| 决策 | 为什么这样做/不那样做？ | 4、5、8、21 | 候选表、Decision Log |
| 落地 | 数据、AI、系统和人如何闭环？ | 6—16 | 手绘图、功能卡、评测表 |
| 答辩 | 哪些是真实证据，约束变化后怎样？ | 17—22 | Trace、Bad Case、讲稿、证据索引 |

## 3. “教会”而不是“代写”

每个高难模块使用三层：

### 层 1：先解释

- 这个模块为了解决什么业务/决策问题；
- 不做会怎样；
- 与相邻模块的边界。

### 层 2：给一个完整 Case

Case 包含角色、输入、版本、证据、判断、异常、人工和结果。让抽象方法产生体感。

### 层 3：让学员重做

要求学员：

1. 关闭案例；
2. 换成自己的用户、对象、规则和风险；
3. 独立产出；
4. 再用清单查漏；
5. 写出与案例不同的一个 Corner Case。

AI 可以：

- 提醒缺字段；
- 挑战 Why；
- 检查矛盾；
- 生成测试变体。

AI 不应：

- 替学生决定业务事实；
- 代画最终流程；
- 编造模型对比结果；
- 把示例阈值当企业标准；
- 生成漂亮原型冒充用户验证。

## 4. 迁移练习

### 每章最低练习

1. **变量表**：本章哪些是通用方法，哪些依赖行业/公司/场景？
2. **反例**：什么情况下本章方案不成立？
3. **约束变化**：预算减半、无私有化、数据减半、流量十倍、安全升级后怎样改？
4. **自有 Case**：一正常、一异常、一 Corner Case。
5. **产物**：表、图、规则、Schema、评测或 Runbook 中至少一个。

### 不可复制的内容

- 合同审查案例的规则编号、阈值和法务结论；
- 某模型在未复测环境中的胜出结论；
- 某企业权限、系统、SLA 和人工容量；
- 未经证明的指标和 ROI；
- 示例项目作者的个人职责。

## 5. 面试卡

每个重大决策提供：

| 字段 | 要求 |
| --- | --- |
| 主问 | 紧扣本项目事实或设计 |
| 约束追问 | 改变预算、数据、风险、时延、权限或规模 |
| 考察点 | 面试官想听的判断和证据，不是标准答案 |
| 答题主线 | 场景→约束→候选→决策→证据→结果/待验证→反思 |
| 可展示产物 | PRD、流程、规则、Schema、Eval、Trace、Bad Case |
| 红旗 | 套话、编造、职责膨胀、只讲技术 |

### 高频主问

#### 业务与 MVP

- 为什么优先这个场景？
- 不做 AI、只改流程或用规则能否解决？
- 业务量更大但规则不成熟的场景为什么不先做？
- 一期删掉什么，如何保证最小闭环？

#### 功能与系统

- 一个请求从进入到正式结果经过什么对象和状态？
- 旧任务晚到、重复提交、外部超时未知如何处理？
- 产品定义了什么，研发/算法实现了什么？

#### Rule/RAG/LLM

- 规则审查与 RAG、LLM 分工是什么？
- 为什么不让大模型直接判断企业政策？
- 案例和规则冲突怎么办？
- 如何证明 Chunk/Embedding/Rerank 适合当前场景？

#### Schema/校验

- JSON 结构正确但结论错误怎么办？
- 引用存在但不支持结论如何发现？
- 哪些业务不变量必须确定性校验？

#### 评测

- 评测数据从哪里来，为什么代表真实和高风险分布？
- Gold 如何标，专家意见冲突怎么办？
- 离线变好但用户总时长变差是否上线？
- 高风险 Recall 下降但总准确率上升怎么办？

#### 异常与运营

- 服务挂了为什么不全量转人工？
- 恢复后人工已经处理怎么办？
- 指标下降如何定位不是模型问题？
- 一个 Bad Case 何时真正关闭？
- 政策、模型或知识变更如何发布和补审？

### 约束追问生成法

对当前决策改变一个前提：

- 数据不能出域；
- 预算砍半；
- 时延从分钟变秒；
- 业务量十倍；
- 人工只有一半；
- 新法域/新语言；
- 规则冲突；
- 供应商模型无法锁版本；
- 高风险漏检上升；
- 用户采纳率高但事故增加。

高分回答要指出：哪些目标不变、哪些方案失效、重新评什么、怎样安全过渡。

## 6. 证据与真实性

### 项目成熟度

标记：

- M0 想法；
- M1 调研；
- M2 方案；
- M3 PoC；
- M4 内测；
- M5 灰度；
- M6 上线；
- M7 规模化运营。

不要让 M2 课程方案使用 M6 口吻。

### 证据等级

| 级别 | 示例 |
| --- | --- |
| E0 | 无证据观点 |
| E1 | 公开资料/间接信息 |
| E2 | 用户转述/小样本观察 |
| E3 | 可展示的项目产物、样本、实验 |
| E4 | 真实使用、业务指标、审计或外部结果 |

答辩中主动说明证据等级。缺数据时说：

> 当前是课程/方案阶段，这个数字是目标或示例，不是线上结果。若进入试点，我会先通过……建立基线，再用……验证。

这比编造 95% 更专业。

### 个人职责答题

使用：

`我定义/推动/决策了什么 → 与谁协作 → 对方实现/确认什么 → 我如何验收 → 有什么产物或证据`

不要说“我训练了模型”除非确有实现证据。

## 7. 图和原型训练

### 手绘演练

每张关键图都要求学员在不看文档时重画：

1. 先画用户与业务对象；
2. 再画数据/规则/AI/人工；
3. 标存储、版本和权限；
4. 补异常、降级和恢复；
5. 解释每条箭头为何存在；
6. 删除一个组件，说明业务影响。

文档中 Mermaid 是评审和阅读载体，不是学员最终学习成果。

### 原型演练

没有图片时不虚构。要求学员后续补：

- 受理/输入；
- 解析确认；
- 结果和证据；
- 版本 Diff；
- 人工队列；
- 运营/质量看板。

每个页面标：角色、目标、进入、字段来源、状态、权限、主动作、危险动作、异常/恢复、埋点和需求 ID。

## 8. 最终答辩结构

### 30 秒

`目标用户 + 核心任务/损失 + 一期方案 + AI 增量 + 当前证据状态`

### 3 分钟

1. 背景和问题；
2. 为什么 AI/为什么不是简单方案；
3. MVP 闭环；
4. Rule/RAG/LLM/人工关键设计；
5. 评测和风险；
6. 我的职责与结果/待验证；
7. 一个关键取舍。

### 10 分钟

补充：

- 全链路图；
- 数据和模型选型；
- 一个正常 Case；
- 一个失败/Bad Case；
- 降级恢复；
- 上线运营；
- Decision Log 和反转判断。

结束不是“项目取得巨大成功”，而是说明当前证据、限制和下一项最值得验证的决策。
